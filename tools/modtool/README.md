# 东方星莲船 魔改工具

一个本地网页版（Web UI）的《东方星莲船》(TH12) 魔改工具，可以修改
**贴图、音乐、对话文本、音乐室评论，以及归档里的任意文件**。

日文版（`th12.dat`）和汉化版（`th12c.dat`）都支持，修改前会自动备份。

---

## 一、怎么用

双击 **`启动魔改工具.bat`**，浏览器会自动打开 `http://127.0.0.1:8765/`。

也可以手动启动：

```bat
python tools\modtool\server.py
```

可选参数：

| 参数 | 说明 |
| --- | --- |
| `--port 8765` | 指定端口 |
| `--no-browser` | 不自动打开浏览器 |
| `--game-dir "路径"` | 指定游戏目录（默认是 `game/[th12] 东方星莲船 (汉化版+日文版)`） |

> 🛑 **修改前必须完全退出游戏**，而且要**关干净**（任务管理器里不能有
> `th12.exe` / `th12c.exe`）。理由不只是"文件被占用"：游戏运行时它的数据文件
> 往往**仍然可以写入**，这时硬写会直接**写坏游戏文件**。
> 工具现在会先检查进程，发现游戏在运行就拒绝写入并提示你退出。

### 换成另一份 TH12 游戏文件

工具支持任意目录，只要那个目录里有游戏数据文件即可：

- 最少需要 `th12.dat`（日文版）**或** `th12c.dat`（汉化版）
- 想改音乐还需要 `thbgm.dat`（约 400MB）
- `th12.exe` / `th12c.exe` 不是必须的，但**有的话可以直接在网页里点“启动游戏”**

四种用法任选：

1. **网页里设置**（推荐）：右上角 **⚙ 设置目录**。

   **两种填法都行**：

   - **直接选文件**（最省心）：点「选文件…」选 `th12.dat` 或 `th12c.dat`；
     也可以直接把那个文件拖进输入框 / 粘贴它的路径。
     `thbgm.dat`、`th12.exe` 等同目录文件也认，工具会自动定位到所在目录。
   - **选目录**：点「选目录…」，或在输入框里粘贴目录路径。

   弹窗里还会显示：

   - **当前状态**：已经连上哪一份游戏，或者提示还没设置
   - **实时校验**：边填边检查，直接告诉你这个路径能不能用
   - **扫描到的游戏目录**：自动列出本机所有找到的 TH12 目录，点一下就能填入；
     找不到时点「重新扫描」（会做一次更深的搜索）

   几个贴心之处：

   - 选到**上一级**目录（比如选到 `game\` 而不是 `game\TH12\`）不会报错，
     工具会自动找到里面的游戏目录并告诉你
   - 目录里**没有游戏数据**时会明确说明，并提示该选哪一层
   - 目录里有**损坏的归档**（以前写坏过）会当场警告，说清哪个文件有问题
   - 设置结果记进 `tools/modtool/config.json`，下次启动自动记住

2. **把游戏文件夹直接拖到 `启动魔改工具.bat` 上**，会自动以该目录启动。

3. **命令行指定目录**：
   ```bat
   python tools\modtool\server.py --game-dir "D:\我的游戏\th12"
   ```

4. **把游戏文件放进默认目录**：
   `game/[th12] 东方星莲船 (汉化版+日文版)/`

> 以前启动时如果没配好目录，会强制弹出设置窗口挡住整个界面；现在改成
> 顶部「⚙ 设置目录」按钮高亮提示 + 一条提示语，界面本身照常可用。

### 网页里启动游戏

右上角 **▶ 启动游戏** 按钮会运行当前版本对应的
`th12.exe` / `th12c.exe`（工作目录设为游戏目录）。

> 改完贴图/音乐后，先关掉游戏再改，改完点“启动游戏”即可验证。
> 游戏运行时数据文件可能仍可写入，硬写会**写坏游戏文件**，不是简单的“被占用”。
> 工具会预检查进程，检测到游戏在运行就拒绝写入。

> 注意：工具是按 **TH12** 的参数写的（归档加密参数、thbgm.fmt 结构等）。
> 换成 th11 / th13 等其他作品的 .dat 无法解析。

## 二、功能

> **工作流：改完记得点保存。**
> 所有修改（贴图 / 对话 / 文件 / 音乐）都是先**暂存**，不会立刻动游戏文件。
> 页面底部会出现「有 N 项修改待保存」的横条，点 **「保存到游戏…」**
> 才会真正写入，并且可以在保存时**填写备注**（会记进备份和日志）。
> 想反悔就点「放弃」。

### 1. 贴图（.anm）
- 左侧列出归档里的 `.anm` 文件，点开后可看到里面所有贴图的**实时预览**
- 顶部搜索框可以**按贴图名全局搜索**（跨所有 ANM），例如输入
  `etama`、`face02no`、`stage04e`，甚至直接输 `bullet.anm` 看整个文件；
  结果会显示每张贴图所在的 ANM、序号、尺寸、格式
- 支持 PNG **导出 / 替换**；替换时自动按原格式（BGRA8888 / RGB565 /
  A4R4G4B4 / GRAY8）重新编码写回
- 支持改变贴图尺寸（一般建议保持原尺寸，否则精灵坐标可能需要一起调整）

### 2. 音乐（thbgm.dat + thbgm.fmt）
- 列出 18 首 BGM（时长、循环点）
- **波形播放器**：点「▶ 试听」展开，能看到整首曲子的波形
  - **点波形**跳到该位置；右侧显示当前时间 / 总时长
  - **循环区**（A → 曲尾）用蓝色标出，一眼看出会循环哪一段
  - **拖动 A 标记**直接改循环点（松手即生效，不用再点按钮）
  - **↺ 设为当前位置**：把循环点设成当前播放位置，边听边定最方便
  - 播放到曲尾会自动跳回循环点，模拟游戏里的循环行为
- 支持在线**试听**、导出 WAV、上传 WAV 替换
- 上传的音频会自动转换成游戏需要的 **16bit / 立体声 / 44100Hz**
- 循环点也可以直接填秒数（表格里那一列），输入框上限就是**源音频的真实长度**
  （替换过按新音频算、改过循环点按暂存里的原始音频算）
- 音乐修改同样是先暂存，跟着页面底部的「保存到游戏」一起写入
  （重建 `thbgm.dat` 约 400MB，需要等几秒到几十秒）

> **循环点是怎么实现的（重要）**
>
> `thbgm.fmt` 里确实有一个 `loop` 字段，但 **TH12 的播放引擎不读它** ——
> 引擎只按 `begin_pos` 定位、按 `unknown` 把整块音频读进内存，然后**整块循环
> 播放**。所以「只改这个字段」在游戏里永远听不出变化。这一点用三重取证确认过
> （打开函数只访问 `+0x10`/`+0x14`；全 exe 搜「fmt 基址 → `+0x18`」命中 0 处；
> 条目指针表的消费者也只读 `+0x14`），证据见
> [`_recon/README.md`](../../_recon/README.md) 与
> [`_recon/th12_loop_decisive.py`](../../_recon/th12_loop_decisive.py)。
>
> 因此保存时会**改音频**。既然引擎是把整块缓冲循环播放，那只要让
> **缓冲内容本身**就是你要反复听的那一段即可：
>
> ```
> 循环体 = 源音频[循环点 : 曲尾]
> 轨道内容 = [循环体][循环体]     长度 = 2 × 循环体
> loop 字段 = 循环体长度
> ```
>
> 于是**一进游戏就在循环**，不存在「前奏播一遍」的阶段。
> `loop` 写在循环体长度处是双保险：即使引擎改成在 `loop` 字段处回跳，
> 落点也还是循环体，听感一致。
>
> 由此带来两个必须知道的点：
> - **循环点之前的部分会被丢弃**。「循环点」的含义是「从这里开始循环」；
>   想让整首循环就把循环点设为 0。
> - **接缝是硬切**。循环体末尾接回自己开头，乐器会断一下；原曲的 `loop` 值
>   本来就是作曲者标的自然衔接点，所以断点通常很轻微，但绝不是无缝的。
>
> 反复改循环点不会累积：第一次设定时会把**未拼接的原始音频**存一份到暂存目录，
> 之后每次保存都从它重拼；替换成新音频时这份暂存会跟着更新。

### 3. 对话（.msg）
- 按条目展示每条对话的文本，**每句前面标出说话人**：
  `自机`（博丽灵梦 / 雾雨魔理沙 / 东风谷早苗）、
  `敌机`（按关卡显示 Boss 名，如「云居一轮」）、`旁白`
- 文件名自动解析出 **角色 / 关卡 / Boss / 场景**，显示在标题栏
- 可直接在网页里编辑并保存；日文版按 Shift-JIS、汉化版按 GBK 编码
- **导出文档**：导出一份 UTF-8 文本，交给翻译/校对
  （格式 `[条目.指令] [说话人] 文本`，用任何文本编辑器改都行）
- **导入文档**：把改好的文档传回来，先**弹窗预览每一处改动**（旧 → 新），
  确认后才写入；无法识别的行会跳过，用了目标编码表示不了的字符会警告
- 非文本指令（演出、等待、立绘等）原样保留

### 4. 批量导入（按文件名自动替换）
「批量导入」页可以直接**选择一个文件夹**（或一堆文件），工具按文件名自动识别：

| 文件名示例 | 识别为 |
| --- | --- |
| `face02no.png` | **按贴图名匹配**（推荐）：找到游戏里所有叫 `face02no.png` 的贴图；尺寸等于“合成画布”时自动按各条目的 x/y 切分回填 |
| `ascii.anm_0.png` | `ascii.anm` 的第 0 张贴图 |
| `etama@bullet@0.png` | `bullet.anm` 的第 0 张贴图（thanm 风格） |
| `st01_00a.txt` | `st01_00a.msg` 的对话文档（列表里显示“将修改 N 句”，可点“预览改动”） |
| `stage01.ecl`、`st01_00a.msg` … | 与归档同名，原样替换 |
| `musiccmt.txt` | 音乐室评论 |

**关于合成图**：游戏里同一张贴图可能被拆成好几块（例如
`face02no.png` 在 `stgenm02.anm` 里是 337×256 + 337×128 + 337×32 三块，
按 y 偏移叠成 337×416）。如果你手上的 PNG 正好是 337×416，
工具会自动按每块的 x/y 切回去；如果只是其中一块的尺寸，就只替换那一块。

识别不了的文件会标成“未识别”并自动跳过。确认无误后点「应用全部」，
每个归档只写一次，并自动备份。

> 首次构建“贴图名索引”需要解压全部 .anm（约 30 秒，后台自动预热），
> 之后会缓存到 `tools/modtool/staging/`，再导入就是秒级。

### 5. 任意文件
- 归档里所有文件（`.ecl` 弹幕脚本、`.sht` 自机、`.std` 关卡、`.rpy` 录像…）
  都可以导出备份 / 原样替换

### 6. 音乐室评论
- 直接编辑 `musiccmt.txt`

### 7. 日志
- 记录所有写操作（替换贴图、保存对话、导入文档、重建音乐、还原备份…）
- 网页「日志」页可查看 / 刷新 / 清空 / 导出
- 同时保存在 `tools/modtool/logs/modtool.log`（JSON Lines，可脚本分析）

### 8. 备份 / 还原
- 第一次修改某个文件前会自动生成 `xxx.modtool.bak`（保留最原始版本，之后不再覆盖）
- 「备份时间」显示备份生成时间（不是游戏文件 2009 年的时间戳），
  并标出当前文件是否在备份之后被改过（大小/时间任一不同即算改过）
- 还原前会把当前文件另存为 `xxx.modtool.prev`，误点也能找回来
- 支持单个还原、下载备份，以及「全部还原」
  （日文版/汉化版共用 `thbgm.dat`，改过音乐时建议用「全部还原」保持状态一致）

## 四、格式说明（给想继续折腾的人）

### THA1 归档（th12.dat / th12c.dat）
```
0x00  16 字节头（整体加密）: "THA1" + list_size + list_zsize + entry_count
      三个字段分别加常量 123456789 / 987654321 / 135792468
0x10  条目数据（每条按文件名和 &7 选一组密码参数加密）
末尾  条目表（LZSS 压缩 + 加密）
条目表项: name(补零到 4 字节) + u32 offset + u32 size + u32 0
```

### ANM 贴图
TH12 使用 `anm_header11_t`（version=7），条目通过 `nextoffset` 串成链，
贴图数据在 `THTX` 块里：

| format | 含义 | 每像素 |
| --- | --- | --- |
| 1 | BGRA8888 | 4 字节 B,G,R,A |
| 3 | RGB565 | 2 字节 LE，R5<<11 \| G6<<5 \| B5 |
| 5 | A4R4G4B4 | 2 字节 LE，A4<<12 \| R4<<8 \| G4<<4 \| B4 |
| 7 | GRAY8 | 1 字节灰度 |

### BGM
`thbgm.dat` 头部 16 字节（`ZWAV`），之后是连续的 16bit 立体声 PCM；
`thbgm.fmt` 放在归档里，每条 0x34 字节：

```
0x00 name[16]
0x10 u32 offset    在 thbgm.dat 中的偏移
0x14 u32 preload   预读字节数（引擎按它 malloc 并读入整条曲子）
0x18 u32 loop      循环起点（相对 offset）—— 注意：TH12 引擎不读这个字段
0x1C u32 end       长度
0x20 WAVEFORMATEX 16 字节
0x30 u32 zero
```

> `loop` 字段在 TH12 里是**死数据**（引擎只读 offset 与 preload，见上文
> 「循环点是怎么实现的」）。本工具保留它是为了不改动无关字节，并把它当作
> 用户设定的循环点来记录；真正生效的是保存时的音频拼接。
>
> 原版 18 条轨道的 `preload` 一律大于 `end`（1.03~1.29 倍），也就是
> 「预读缓冲必须覆盖整段音频」。替换/拼接后的轨道也必须满足这一点，
> 否则循环体会被截断 —— `rebuild_bgm_dat` 会强制 `preload >= length`。

### .msg 对话
```
u32 entry_count
entry_count × (i32 offset, i32 extra)
指令流: u16 time, u8 type, u8 length, u8 data[length]
文本 = type 17，数据用滚动密钥 XOR 混淆（key=0x77, +7, +16）
```

## 五、已知限制

- 音乐只支持未压缩 PCM WAV 上传（其他格式请先转成 WAV）
- 贴图改尺寸后，引用它的精灵显示位置可能需要另行调整
- 重建 `thbgm.dat` 需要约 1 倍文件大小的临时空间
- 弹幕脚本（.ecl）只支持原样替换，没有可视化编辑

## 六、出问题了怎么办

### 设置目录时提示「这个目录里没有 th12.dat / th12c.dat」

**最省事的办法：别选目录，直接选文件** —— 点「选文件…」选那个 `th12.dat`
或 `th12c.dat`，工具会自动用它所在的目录，不用纠结该选哪一层。

如果你还是想选目录，那要选的是**里面直接放着** `th12.dat` 或 `th12c.dat`
的那个文件夹，不是它的上一级。选到上一级也不会报错 ——
工具会自动往下找一层，并把找到的路径填回去。

### 提示「归档像是写到一半中断了」

说明这个 `.dat` 已经被写坏了（条目表指向文件末尾之外）。原因是**以前某次保存
被中断**（断电、强制关闭、磁盘满等）。

好消息是工具每次修改前都会自动备份，直接还原即可：

- 网页 **备份 / 还原** 标签页 → 找到对应文件 → 点还原
- 或者手动：把 `th12.dat.modtool.bak`（最原始的版本）复制成 `th12.dat`

要检查某个目录有没有坏，把路径填进设置弹窗，看实时校验的提示即可。

> 现在的版本写入是**原子操作**（先写临时文件、校验通过才替换），
> 而且写完会自检一遍；万一生成的数据不自洽，会**放弃写入并保留原文件**，
> 不会再写出打不开的归档。

### 音乐页报「读不出 thbgm.fmt」

`thbgm.fmt` 或它指向的 `thbgm.dat` 有问题。这时**贴图、对话、任意文件仍然
可以正常修改**，只有音乐用不了。要修的话：

- 确认游戏目录里的 `thbgm.dat` 和归档里的 `thbgm.fmt` 是配套的
  （日文版和汉化版共用同一个 `thbgm.dat`）
- 或者从备份还原 `th12.dat` / `th12c.dat`

### 我一个游戏都不想要了，想让它干净启动

删除 `tools\modtool\config.json` 即可（里面只记着上次用的路径）。
工具不会自动删除备份文件，`*.modtool.bak` / `*.modtool.prev` 需要自己清理。
